Lesson 2

Enough Go syntax to read a request

Packages, imports, and visibility

package workflow

import (
    "context"                  // standard library
    "fmt"
    "governata.local/store"    // another package
)

func CompleteTask() {}          // exported: capital C
func validateTransition() {}    // package-private: lower-case v

A directory normally represents one package. Capitalization is Go’s access modifier: names starting with an uppercase letter are exported. Unlike JavaScript, imports name packages, and selectors such as workflow.NewEngine name exported members.

Variables, functions, and multiple returns

taskID := c.Param("id")                 // infer local type
task, err := engine.CompleteTask(ctx, taskID)
if err != nil {
    return err                           // errors are values
}
return c.JSON(200, task)                 // explicit happy path

:= declares local variables. Go commonly returns a value and an error together. Read the code as a visible decision tree: call, inspect error, handle it, continue.

Structs, methods, and receivers

type Task struct {
    ID     string `json:"id" gorm:"primaryKey"`
    Status string `json:"status"`
}

type Engine struct { store TaskStore }

func (e *Engine) CompleteTask(ctx context.Context, id string) (*Task, error) {
    // e is the receiver—the closest Go equivalent to a method's `this`.
    return e.store.UpdateStatus(ctx, id, "completed")
}

A struct groups data. A receiver attaches behavior to a type. A pointer receiver (*Engine) lets the method operate on the same instance and avoids copying it. Tags in backticks are metadata read by libraries such as JSON encoders and GORM.

Deep dive: defer and context

defer cleanup() schedules cleanup when the surrounding function returns; common uses are closing rows, spans, or files. context.Context carries cancellation, deadlines, and request-scoped values across a call chain. Put it first in function parameters and do not store it in a long-lived struct.

rows, err := db.QueryContext(ctx, query)
if err != nil { return err }
defer rows.Close()

Lesson 3

Interfaces and dependency injection—the invisible jump

type TaskStore interface {
    Find(ctx context.Context, id string) (*Task, error)
    Save(ctx context.Context, task *Task) error
}

type Engine struct { store TaskStore }

func NewEngine(store TaskStore) *Engine {
    return &Engine{store: store}
}

Go interfaces are implemented implicitly: a type satisfies TaskStore by having those methods. There is no implements keyword for Command-click to follow. To resolve e.store.Save:

  1. Read the interface to understand the contract.
  2. Search for func (... ) Save( or use “Go to implementations.”
  3. Find NewEngine( calls in startup code.
  4. See which concrete store is passed at runtime.

Routes, handlers, services, repositories, migrations

MigrationSchema history, constraints, indexesRuntime request logic
protected.POST("/tasks/:id/complete", taskHandler.Complete)

func (h *TaskHandler) Complete(c *gin.Context) {
    task, err := h.engine.CompleteTask(c.Request.Context(), c.Param("id"))
    if err != nil { writeError(c, err); return }
    c.JSON(http.StatusOK, task)
}

The router is the HTTP wiring table. The handler translates protocols. The engine protects domain truth. This separation is the backbone of later phases.

Guided trace

Follow “Complete task” through real Governata

Open these local files in order. At every stop, write one sentence: “this layer receives ___, decides ___, and passes ___.”

  1. React task page — find the complete action.
  2. Frontend API client — find the method and HTTP contract.
  3. Go router — find the route and middleware group.
  4. Task handler — identify decoding, service call, response.
  5. Workflow engine — locate completion and transition validation.
  6. PostgreSQL task store — inspect the model and persistence calls.
  7. Migration — search for the task table.
  8. Composition root — find where dependencies are constructed.
Navigation recipe: for an HTTP gap, search a path fragment such as complete. For an interface gap, search constructor calls and method implementations. For an event gap, search the subject string or constant. For a database gap, search table/model names in migrations.

Practice

Three sessions that build the map

Session A — Read a tiny Go file

Write a 25-line main.go containing a Task struct, Status named type, Complete method, and error for an invalid transition. Predict every value before running it.

Session B — Draw the trace

Trace Governata’s Complete action using the links above. Mark edges as CALL, HTTP, INTERFACE, DATABASE, or MESSAGE.

Session C — Teach it back

Without looking, explain why TaskStore.Save may not navigate to PostgreSQL and how startup wiring resolves the concrete type. Then repeat the trace from memory.

Common traps

  • Trying to learn every Go keyword before reading product code.
  • Assuming a handler contains the entire feature because it is the HTTP entry point.
  • Searching only function names when the connection is a route string or message subject.
  • Treating a GORM struct as the whole database contract; migrations and constraints also matter.
  • Reading files linearly instead of following a single user-visible behavior.

Knowledge check

1. Why can Command-click cross engine.CompleteTask but not reliably cross fetch("/tasks/42/complete")?

Show answer
The first is a symbol in the compiled import/type graph. The second is a runtime string contract between processes; connect it by searching the HTTP method and path.

2. A service field has type TaskStore. Where do you discover the runtime implementation?

Show answer
Inspect types implementing the interface, then find the constructor call in the composition root/startup code to see which concrete value is injected.

3. Where should “a completed task cannot return to pending” live?

Show answer
In the domain service/workflow engine so every transport and caller shares the same invariant. The UI may also guide users, but it is not the authority.
