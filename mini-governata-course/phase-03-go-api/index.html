What you will build

A Go service exposing asset and task endpoints from memory. The React app talks to it through the same API client. Errors have a consistent JSON shape, CORS is limited to the frontend origin, and handler tests run without opening a real port.

type CreateTaskRequest struct {
    AssetID string `json:"assetId" binding:"required"`
    Title   string `json:"title" binding:"required,min=3,max=120"`
}

func (h *Handler) CreateTask(c *gin.Context) {
    var req CreateTaskRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        writeError(c, http.StatusBadRequest, "invalid_request", err.Error())
        return
    }
    task, err := h.service.Create(c.Request.Context(), req.AssetID, req.Title)
    if err != nil { h.writeDomainError(c, err); return }
    c.JSON(http.StatusCreated, toTaskResponse(task))
}

DTOs describe transport input/output. Domain types describe business truth. Mapping looks repetitive, but it prevents JSON or framework concerns from leaking into the core.

Map known domain errors centrally with errors.Is. Do not return raw database or stack messages to the browser.

Middleware and context

Order changes behavior

router := gin.New()
router.Use(gin.Recovery())
router.Use(RequestID())
router.Use(AccessLog())
router.Use(CORS(frontendOrigin))

api := router.Group("/api/v1")
api.GET("/health", health)
api.POST("/tasks", handler.CreateTask)

Middleware wraps downstream work. Recovery should prevent a panic from killing the process; request IDs should exist before logs; auth must run before authorization. Pass c.Request.Context() into services so client cancellation and server deadlines can stop work.

Deep dive: CORS

CORS is a browser rule controlling which origins may read responses. During development, allow the exact Vite origin and needed methods/headers. It is not authentication and does not protect the API from non-browser clients.

Server lifecycle

Start and stop intentionally

srv := &http.Server{Addr: ":8080", Handler: router}
go func() {
    if err := srv.ListenAndServe(); !errors.Is(err, http.ErrServerClosed) {
        log.Fatal(err)
    }
}()

<-shutdownSignal
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(ctx)

Graceful shutdown stops accepting new work and gives in-flight requests a deadline to finish. Later, database connections, message consumers, and workers join this lifecycle.

Tests

Exercise routes in memory

func TestCreateTask(t *testing.T) {
    router := newTestRouter(fakeService{})
    body := strings.NewReader(`{"assetId":"a1","title":"Review owner"}`)
    req := httptest.NewRequest(http.MethodPost, "/api/v1/tasks", body)
    req.Header.Set("Content-Type", "application/json")
    rec := httptest.NewRecorder()

    router.ServeHTTP(rec, req)
    if rec.Code != http.StatusCreated { t.Fatalf("status = %d", rec.Code) }
}

Test one happy path and important boundary failures: malformed JSON, validation, missing task, invalid transition, and internal failure sanitization. Service tests already prove domain rules.

Integration sequence

  1. Write an API contract table before handlers.
  2. Create DTOs and one error envelope.
  3. Wire Gin routes to the Phase 2 service.
  4. Add request ID, recovery, logging, and restricted CORS.
  5. Test every endpoint with httptest.
  6. Run React with MSW disabled and configure the API base URL.
  7. Use browser network tools to inspect actual request/response pairs.
  8. Add graceful shutdown and configuration validation.

Knowledge check

1. Why pass request context into the service?

Show answer
Cancellation and deadlines can propagate to database/message operations instead of doing abandoned work after the client or server times out.

2. Is CORS security for the API?

Show answer
No. It controls browser response access across origins. Authentication and authorization protect the API.

3. Why separate DTO and domain model?

Show answer
Transport shapes evolve for clients, while domain models express rules. Separation prevents JSON/framework details from controlling business logic.
