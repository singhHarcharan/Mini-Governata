Why CEL

Expressions, not arbitrary application code

// Example CEL expressions
asset.classification != "confidential" || asset.owner != ""
task.status == "completed" ? task.assignee != "" : true
request.roles.exists(r, r == "governance_admin")

CEL is a non-Turing-complete expression language designed for fast, safe evaluation against a declared environment. It is suitable for predicates and computed values, not database writes, loops with side effects, or unconstrained scripting.

Application code

Owns workflow, persistence, I/O, security, and the policy lifecycle.

CEL expression

Evaluates a decision from the bounded facts the application supplies.

Environment

Declare what a policy is allowed to see

env, err := cel.NewEnv(
    cel.Variable("asset", cel.MapType(cel.StringType, cel.DynType)),
    cel.Variable("task", cel.MapType(cel.StringType, cel.DynType)),
    cel.Variable("request", cel.MapType(cel.StringType, cel.DynType)),
)

ast, issues := env.Compile(expression)
if issues != nil && issues.Err() != nil {
    return fmt.Errorf("compile policy: %w", issues.Err())
}
program, err := env.Program(ast)

Compile when a policy is created/activated, not on every request. A stricter typed object environment catches more mistakes than dynamic maps. Expose only required, sanitized facts—never database handles, secrets, or broad internal objects.

For enforcement policies, fail closed unless the product explicitly defines another safe mode. For advisory policies, an evaluation failure may create a visible warning rather than block.

Lifecycle

A policy is a versioned governed artifact

type PolicyVersion struct {
    PolicyID      string
    Version       int
    Expression    string
    Effect        string // enforce | advise
    Status        string // draft | active | retired
    CreatedBy     string
    CreatedAt     time.Time
    SchemaVersion int
}
  1. Draft expression and metadata.
  2. Compile and show diagnostics with location.
  3. Test against representative fixtures.
  4. Approve/activate an immutable version.
  5. Evaluate that exact version.
  6. Retire by activating a later version; retain historical evidence.

Never silently edit an active policy because old decisions would become impossible to reproduce.

Decision record

Make “why” inspectable

type PolicyDecision struct {
    PolicyID, PolicyVersion string
    EntityType, EntityID    string
    Result                  bool
    Effect                  string
    EvaluatedAt             time.Time
    ContextDigest           string
    ErrorCode               string
    CorrelationID           string
}

Record policy/version, target, outcome, time, and correlation. A digest can prove which normalized context was used without storing all sensitive inputs. Give policies human descriptions and remediation messages; raw expressions alone are poor UX.

Policy tester

Design fast feedback before activation

  1. Editor accepts an expression and displays variables/operators available.
  2. “Compile” returns precise diagnostics and prevents invalid activation.
  3. Sample JSON context is schema-validated.
  4. “Evaluate” shows result, policy effect, and a plain-language message.
  5. Fixture table covers allowed, denied, missing, and wrong-type cases.
  6. Activation requires version metadata and permission.

Knowledge check

1. Why compile on activation?

Show answer
Invalid expressions are rejected early, compiled programs can be cached, and request latency avoids repeated compilation.

2. Is false an evaluation error?

Show answer
No. It is a valid decision. Errors mean the expression/context could not be evaluated as designed.

3. Why version policies immutably?

Show answer
Historical decisions must identify the exact rule evaluated, enabling audit, rollback, comparison, and reproducibility.

Common traps

  • Allowing policy expressions to fetch data or cause side effects.
  • Compiling on every evaluation.
  • Passing unbounded internal objects into activation context.
  • Treating evaluation errors as ordinary denials without recording the distinction.
  • Editing active expressions in place.
